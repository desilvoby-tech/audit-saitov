| Шаг | desilvo.by | redsale.by |

## Что работает хорошо

- Пошаговый мастер с прогрессом, вопросы по услуге, автопереход при одиночном выборе — на уровне образца.
- Подсказка не писать телефон в описании, адрес — только район (точный — выбранному мастеру).
- Защита от двойной отправки (`go.disabled=true`), черновик переживает перезагрузку вкладки.
- Бюджет «договорная» по умолчанию — у образца такого шага нет, это плюс desilvo.

## Найденные проблемы

1. **Задание публикуется без подтверждения телефона.** Аноним вставляет запись в `requests` с любым номером. Можно создать задание на чужой номер — этот номер потом увидит выбранный мастер; плюс риск спама. У образца — вход по коду SMS до публикации.
2. **Нет текста о согласии на обработку персональных данных** на шаге «Контакты», хотя собираются имя и телефон. На экране входа/регистрации desilvo такой текст есть, а здесь — нет. *Юридическую формулировку согласовать владельцу* (связано с модулем 10).
3. **Задание анонима, вероятно, не привязывается к аккаунту.** В `insert` нет `client_id`; «Мои задания» выбираются по `client_id = uid()`. После публикации гостю предлагают «войти по этому номеру», но неясно, появится ли задание в кабинете. *Проверить на стороне БД*: есть ли default `auth.uid()` / триггер привязки по телефону.
4. **Ответы на вопросы не обязательны.** Можно пройти все шаги, ничего не выбрав, — мастер получит задание без деталей. У образца ответ обязателен.
5. **Поиск на шаге «Услуга» — отдельный, старый.** Здесь своя подстрочная фильтрация `ALLSVC().filter(...includes(q))` без ё/е, словоформ и опечаток. Новый поиск из PR #1 (решение владельца, этап 1) сюда **не попадает**. При пустом результате — только текст «опишите своими словами».
6. **Свободный текст — без категории.** `vNew(pre)` при ненайденной услуге сразу ставит шаг 1 (это уже «Пожелания»), вопросы пропускаются. Совпадает с проблемой 6 модуля 2; по решению владельца нужно: уверенное совпадение → услуга, иначе 2–3 похожих на выбор.
7. **Переход с главной (`#new-<услуга>`) молча стирает черновик** (`saved&&!pre?saved:…`). Пользователь, начавший задание и вернувшийся через поиск, теряет введённое.
8. **Устаревшая дата в черновике.** Если черновик восстановлен на следующий день, выбранная дата может быть в прошлом — проверки нет, она уходит в `deadline`.
9. **Бюджет без проверки.** `min="0"` только подсказка браузеру: «-5» или «1000000» уйдут в базу как есть.
10. **Телефон проверяется только на ≥9 цифр**, без маски и формата +375. Имя не обязательно.
11. **Нет фото к заданию.** Для ремонта/поломок фото сильно помогает мастеру назвать цену. Механизм уменьшения фото (`shrink`) на сайте уже есть (портфолио мастера).
12. **Нет шага «Проверьте задание»** перед публикацией — пользователь не видит итог (услуга, ответы, дата, бюджет) до кнопки «Опубликовать».
13. **Кнопка «Назад» браузера** выкидывает из формы, шаги не отражаются в адресе.
14. **(мелочь)** В коде осталась старая форма `vNewOld` с отдельным `insert` — проверить, недостижима ли она, и удалить.

Вариант Б (мягче): задание сохраняется со статусом `pending`, мастерам не показывается, пока номер не подтверждён. На стороне БД — политика RLS: `insert` в `requests` только для `authenticated` и `client_id = auth.uid()`.

```sql

  with check (client_id = auth.uid());
```

- Чтение репозитория `migom` через коннектор было отклонено в этом запуске — код взят с живой страницы.
