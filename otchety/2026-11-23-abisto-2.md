## Найденные проблемы

1. **Поиск ищет фразу целиком, без форм слов и порядка (главное).** Сервер ищет запрос как одну подстроку. Проверено на живом сайте:
   - «угловой диван» → 0 (есть «Диван угловой»); «машина стиральная», «стиральную машину», «стиральные» → 0 (есть «Стиральная машина…»);
   - «ремонт ноутбука» → 0 (есть 3 объявления «Ремонт ноутбуков…»); «ноутбука», «рюкзаки», «микроволновку» → 0;
   - «елку» → 0, «ёлку» → 1 (ё и е различаются);
   - «eco 235» → 0 (есть «Eco-235»); «ремонт,телефонов», «ремонт (телефонов)» → 0;
   - «гомель» → 0, но «Гомеле» → 14.
   Покупатель видит «Ничего не найдено», хотя объявление есть.
2. **Символы `%` и `_` работают как шаблон.** Запросы «%», «_», «р%т» отдают все 41 объявление; «100%» находит лишнее. В подсказках (`abistoSuggest`) эти символы уже вырезаются, в основном поиске — нет.
3. **Фильтры не попадают в адрес страницы.** Ссылкой на поиск нельзя поделиться, закладка и обновление страницы (F5) сбрасывают все фильтры; переход по `#c/раздел` тут же стирает адрес до `#`. Из адреса читается только `?q=`. У Куфара запрос и регион хранятся в ссылке.
4. **Ошибка базы на экране при вводе цены.** Поле цены пропускает «1.2.3» (и «1..5»), сервер отвечает «invalid input syntax for type numeric», пользователь видит «Не удалось загрузить объявления». Запятая выбрасывается: «1,5» превращается в 15.
5. **«от» больше «до» — молча пусто.** Цена от 300 до 100 → 0 объявлений без подсказки; то же для числовых полей (год, пробег, площадь).
6. **Гонка запросов.** `renderHome` не проверяет, что ответ относится к последнему запросу: при быстрой смене фильтров ответ на старый запрос может прийти позже и показать чужую выдачу; `homeItems` перезаписывается даже после ухода со страницы. «Показать ещё» может дописать объявления от прошлого фильтра.
7. **Раскладка клавиатуры.** «ghjlfv» (= «продам») → 0. Для desilvo.by владелец уже решил исправлять раскладку (resheniya.md, 22.11) — предлагаем то же для Абисто.
8. **Мелкое (без патча):**
   - сервер принимает `limit` 1000 и отрицательный `offset` (ошибка базы наружу) — поставить пределы в `search_ads` (в SQL-заготовке есть готовые строки);
   - «Сбросить фильтры» (`fReset`) сбрасывает и подкатегорию, а «Сбросить всё» в чипах — нет; стоит сделать одинаково;
   - выбор подсказки-категории (`abistoPick`) сохраняет область, но теряет город;
   - опечатки («холодильнек») и бытовые синонимы («стиралка») не находятся — следующий шаг после П1 (как этап 2 для desilvo.by: словарь синонимов, `pg_trgm`).
9. **Проверено, не ошибки:** сортировки «дешёвые/дорогие/популярные» работают; «Договорная» не попадает в фильтр по цене (как у досок объявлений обычно); фильтры региона, города, «с фото», «с доставкой» отдают правильные выборки.

## Что предложено (ничего не применено)

**Патч для zis-baraholka:** `patches/2026-11-23-abisto-2.patch` (нулевой контекст, как в модуле 1). Меняет `index.html` и добавляет файл-заготовку `tools/migration-2026-11-23-search.sql`.

- **П1 (SQL, заготовка, НЕ применена).** Функции `ad_text_match`, `ad_norm`, `ad_num`. Поиск: сначала подстрока целиком (как сейчас), затем «все слова как подстроки в любом порядке», затем русская морфология (`plainto_tsquery('russian')`), ё = е, без шаблонов LIKE. На заголовках реальных объявлений: «угловой диван», «стиральную машину», «ремонт ноутбука», «елку», «eco 235», «рюкзаки», «микроволновку», «ремонт,телефонов» — все находятся. Подключение — замена одного условия в `search_ads` (в файле написано как); там же строки для пределов `limit/offset` и безопасных чисел. Индекс не нужен при текущем объёме; при росте — добавить GIN по `to_tsvector`.
- **П2.** Фильтры в адресе: `?q=…&cat=…&sub=…&region=…&city=…&min=…&max=…&sort=…&e.поле=…&f.поле=…&t.поле=…`. Адрес обновляется через `replaceState` (кнопка «Назад» работает как раньше), при открытии ссылки фильтры восстанавливаются и проверяются (неизвестные раздел/регион/сортировка отбрасываются). Чужие параметры (например, `?code=` входа через почту) не трогаются.
- **П3.** Числа: «1,5» → 1.5, «1.2.3» → 1.23, «.5» → 0.5; если «от» больше «до» — значения меняются местами (цена и числовые поля). Основной запрос очищается от `%` `_` `\`.
- **П4.** Защита от гонки: счётчик запросов в `renderHome` и в «Показать ещё».
- **П5.** Раскладка: если по запросу 0 и он набран латиницей, ищем в русской раскладке; если нашлось — показываем выдачу и строку «Показаны результаты по запросу «продам» — исправлена раскладка клавиатуры». Проверено на живых данных: «ghjlfv» → «продам» (5), «lbdfy» → «диван» (1), «cnbhfkmyfz» → «стиральная» (1); «samsung», «ugg» не подменяются (по русскому варианту ничего нет).
- П2–П5 работают и без П1; П1 — отдельный шаг в базе.

Порядок выкладки: `git apply --unidiff-zero --check patches/2026-11-23-abisto-2.patch` → `git apply --unidiff-zero …` → проверить на сайте: поиск, фильтры, F5, ссылку с фильтрами, вход по почте → коммит. Затем, при согласии, П1 в Supabase SQL Editor.
